# 🎯 Module Campagne

## 🧠 Objectif

Le module Campagne est le **cerveau stratégique** de l’application.

Il permet de transformer :
- les données (élections, population, territoire)
- les observations (terrain, réseau)
- le contexte politique (mandat, sujets)

👉 en **décisions concrètes et actions de campagne**.

---

## ❓ Question clé

👉 Comment je gagne l’élection ?

---

## 🧩 Rôle dans l’application

Le module Campagne :

- ne produit pas de données brutes
- n’est pas un CRM
- n’est pas un module d’analyse pure

👉 Il **agrège, priorise et oriente l’action**.

Il s’appuie sur :
- Mandat
- Territoire
- Élections
- Population
- Terrain
- Réseau
- Agenda
- Documentation

---

## 🧱 Structure du module

### 1. Stratégie

#### Objectif
Définir la ligne politique globale.

#### Contenu
- positionnement
- axes prioritaires
- hypothèses de campagne
- angles politiques

#### Contraintes
- doit rester synthétique
- pas de texte long inutile

---

### 2. Objectifs

#### Objectif
Définir des objectifs mesurables.

#### Contenu
- score cible
- zones à conquérir
- participation à augmenter
- couverture terrain

#### Contraintes
- objectifs limités
- mesurables si possible

---

### 3. Zones prioritaires

#### Objectif
Identifier où concentrer les efforts.

#### Sources
- Élections
- Territoire
- Terrain

#### Contenu
- liste de zones
- niveau de priorité
- justification

#### Actions
- voir zone
- planifier action

---

### 4. Cibles

#### Objectif
Identifier les profils électoraux.

#### Sources
- Population
- Terrain

#### Contenu
- segments (jeunes, familles, retraités…)
- préoccupations
- zones associées

---

### 5. Messages clés

#### Objectif
Structurer le narratif.

#### Sources
- Mandat
- Terrain

#### Contenu
- messages principaux
- arguments
- angles par cible

#### Contraintes
- courts
- réutilisables

---

### 6. Plan d’actions

#### Objectif
Organiser l’exécution.

#### Contenu
- actions terrain
- réunions
- événements
- opérations spécifiques

#### Lien
- Agenda
- Terrain

#### Contraintes
- actionnable immédiatement

---

### 7. Suivi de campagne

#### Objectif
Mesurer l’avancement réel.

#### Contenu
- activité terrain
- couverture des zones
- progression des actions
- feedback citoyens

#### Sources
- Terrain
- Réseau

---

### 8. Risques / vigilance

#### Objectif
Anticiper les problèmes.

#### Contenu
- sujets sensibles
- oppositions
- promesses fragiles
- crises potentielles

#### Sources
- Mandat
- Terrain
- Documentation

---

## 🔄 Interactions avec les autres modules

| Module | Interaction |
|--------|------------|
| Mandat | fournit les sujets et promesses |
| Territoire | fournit les zones |
| Élections | fournit les dynamiques de vote |
| Population | fournit les profils |
| Terrain | fournit les retours |
| Réseau | fournit les contacts |
| Agenda | permet de planifier |
| Documentation | fournit les preuves |

---

## 🧠 UX attendue

Le module doit être :

- synthétique
- lisible rapidement
- orienté action

### Règles UX

- éviter les tableaux lourds
- privilégier blocs courts
- toujours proposer une action

### Exemple de vue principale

- 3 zones prioritaires
- 2 messages à pousser
- 5 actions à lancer
- 2 risques à surveiller

---

## ⚙️ Contraintes techniques

- ne pas dupliquer les données
- utiliser des références vers les autres modules
- permettre des mises à jour rapides
- gérer des liens entre entités (zones, promesses, actions)

---

## 🚫 Pièges à éviter

- transformer le module en CRM
- dupliquer le module Terrain
- créer des dashboards complexes
- stocker des données déjà existantes ailleurs
